# Ringee API capability matrix

What Ringee's public API and webhooks can do today, what this node uses, and what is missing. It was written by reading Ringee's source (`ringee-io/ringee-app`), not from memory. **Nothing here is invented:** a capability that does not exist is listed as such, with the closest thing that does.

- **Base URL:** `https://api.ringee.io` for Ringee Cloud (the Dialer SDK, CLI and Attio app use the same address); the API's global prefix is `/api`.
- **Version:** the public API is `/api/v1`. There is no OpenAPI document yet (see [gaps](#gaps-and-recommended-ringee-work)); the contracts below are the source of truth for this repository's types and its mock server.
- **Status key:** ✅ implemented in the node · 🟡 partly, see the note · ❌ not available in Ringee, so not in the node.
- **Availability:** _Existing_ = already in Ringee. _New_ = added in the same change set as this node (`ringee-app`, reviewed but **not deployed**); it reaches Ringee Cloud on deploy and self-hosted installations on upgrade.

## Authentication

| Item        | Behaviour                                                                                                                                                                                     |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Credential  | The key of a **Custom Integration**: `cik_live_` + 64 hex. Created by an organization admin (or a personal workspace owner) in Integrations → Custom Integrations; shown once.                |
| Header      | `X-Ringee-Api-Key: <key>` or `Authorization: Bearer <key>`, never both. The node sends the first.                                                                                             |
| Identity    | **Derived from the stored integration.** The organization and user come from the key; no workspace or user id from the client is ever used (`HOOK-006`).                                      |
| Isolation   | Every read and write is scoped to that workspace by Ringee's ownership filter. Another workspace's id answers `404`, the same as an id that does not exist.                                   |
| Permissions | One level: the key acts for the workspace as its integration owner. There are no per-endpoint scopes. A disabled integration answers `401`.                                                   |
| Rate limit  | New routes (`/v1/contacts`, `/v1/calls`): **600 requests per minute per integration**, then `429` with `Retry-After`. Existing `/v1/ai-voice-agents` routes are not limited at the API layer. |
| Errors      | NestJS shape `{ statusCode, message: string \| string[], error, fields? }`.                                                                                                                   |

## Webhook events (Ringee → n8n)

Sent to the integration's **Outbound URL** for the events it subscribes to (`CustomIntegrationEventType`). Single source of truth in Ringee: `event-spec.ts`.

| Event                  | n8n Trigger               | When                                       | Notes                                                                                                                                                        |
| ---------------------- | ------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `call.completed`       | Call Completed            | The telephony stack reports a call ended   | Also for AI calls. `data.call` may still lack transcript, recording and AI analysis.                                                                         |
| `call.outcome.updated` | Call Outcome Updated      | An outcome is recorded or changed          | Only outcomes in the canonical `CallOutcome` set. Agent-specific ones (`confirmed`, `cannot_attend`, `callback_requested`, `unknown`) are **not** published. |
| `call.failed`          | Call Failed               | A call could not connect                   |                                                                                                                                                              |
| `call.missed`          | Call Missed               | An inbound call was not answered           | `data.fromNumber` is the caller.                                                                                                                             |
| `recording.ready`      | Recording Ready           | A recording was processed                  | Includes the shareable URL, `durationSec` and the transcript when it exists.                                                                                 |
| `meeting.created`      | Meeting Created           | A meeting was booked                       | Fired with `call.outcome.updated` when the outcome is `meeting_booked`.                                                                                      |
| `callback.created`     | Callback Created          | A callback was scheduled                   |                                                                                                                                                              |
| `note.created`         | Note Created              | A note was added to a contact              |                                                                                                                                                              |
| `dnc.created`          | Do-Not-Call Entry Created | A number was added to the Do-Not-Call list |                                                                                                                                                              |

**Envelope:** `{ event, eventId, occurredAt, workspaceId, integrationId, data }`. Events about an AI call also carry `data.agent { id, name }`, `data.externalId` (the External ID given to Start Call), `data.user` and `data.call`.
**Signature:** `Ringee-Signature: t=<unix>,v1=<hex>` and `Ringee-Timestamp`; `v1 = HMAC-SHA256(signingSecret, "<t>.<raw body>")`.
**Delivery:** at least once, queued, 15 s timeout, up to 10 attempts with exponential backoff (2 s doubling, capped at 5 minutes). Each attempt is re-signed with a fresh timestamp; the event id is stable.

## What was asked for, and what exists

| Requested capability                                                                                                                                                            | Status | How it is covered, or why not                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| List / get AI voice agents                                                                                                                                                      | ✅     | Get Many, Get.                                                                                                                                                                                                                                     |
| Start an AI call; status; result                                                                                                                                                | ✅     | Start Call (idempotent), Get Call Status, Get Call Result. Call duration, custom instructions and a contact id are **not** accepted by the API: instructions are configured on the agent, extra context goes in the `additional_context` variable. |
| Human phone calls                                                                                                                                                               | 🟡     | A server cannot place a human call: it needs a person's device. **Create Dialer Link** gives that person a link that opens the dialer ready to call. Get / Get Many read any call. **Hang up** has no API.                                         |
| Contacts (create, get, update, delete, search, list)                                                                                                                            | ✅     | Contact resource, including create-or-update.                                                                                                                                                                                                      |
| Contact lists                                                                                                                                                                   | ❌     | Dashboard only; no public API.                                                                                                                                                                                                                     |
| Campaigns (create, leads, start, pause, stats)                                                                                                                                  | ❌     | Organization-admin functions in the dashboard and the MCP tools; no public REST. Not exposed rather than approximated.                                                                                                                             |
| Recordings (get, download)                                                                                                                                                      | ✅     | Recording resource.                                                                                                                                                                                                                                |
| Transcript, AI analysis, summary, extracted data                                                                                                                                | ✅     | Transcript resource, read from the call detail.                                                                                                                                                                                                    |
| Meetings (availability, schedule, reschedule, cancel, get)                                                                                                                      | ❌     | Meetings exist in Ringee and the MCP can book one, but there is no public REST. The **Meeting Created** event is available.                                                                                                                        |
| Phone numbers / verified caller IDs                                                                                                                                             | ✅     | Phone Number resource (`kind` separates purchased numbers from verified caller IDs).                                                                                                                                                               |
| Triggers: call started, answered, incoming call, voicemail, transcript ready, AI analysis completed, meeting rescheduled/cancelled, contact created/updated, campaign completed | ❌     | Not events Ringee emits. Nearest: Call Completed (+ Get Call Result after a wait), Call Missed, Recording Ready (carries the transcript).                                                                                                          |
| Automatic webhook registration                                                                                                                                                  | ❌     | One Outbound URL per Custom Integration, set in the dashboard; no registration API. See the [proposal](webhook-subscriptions-proposal.md).                                                                                                         |

## Gaps and recommended Ringee work

In order of value to n8n users:

1. **Webhook subscriptions API** (`POST/GET/DELETE /api/v1/webhooks`, one signing secret per subscription). It would let the trigger register on activation and remove itself on deactivation, run test and production side by side, and let many workflows share one key. Needs a table, delivery changes and a migration. [Design](webhook-subscriptions-proposal.md).
2. **Publish AI-agent outcomes as events.** `call.outcome.updated` skips `confirmed`, `cannot_attend`, `callback_requested` and `unknown`, so reminder workflows must wait and read the result. An `ai_voice_agent.call.analyzed` event carrying the result would remove the wait.
3. **Public contact-list, campaign and meeting routes** over the existing services, with the same key and workspace rules.
4. **An OpenAPI document for `/api/v1`**, so this repository can generate and diff its types instead of mirroring them by hand.
5. **A hang-up route** and `call.started` / `call.answered` events.
6. **Per-key scopes** (read-only keys), useful for AI agents that only need to look things up.
